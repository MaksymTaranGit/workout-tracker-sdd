# Конвенція повідомлень комітів (SDD Commit Convention)

Усі коміти в проєкті повинні мати чіткий префікс, що ідентифікує категорію артефакту SDD або характер внесених змін:

- **spec:** Зміни в специфікаціях вимог, контрактах API, математичних моделях (`/spec`).
- **test:** Створення або редагування тестових сценаріїв та наборів тестів (`/tests`).
- **feat:** Реалізація нової функціональності програмного коду системи (`/src`).
- **fix:** Виправлення дефектів та помилок у реалізації коду (`/src`).
- **refactor:** Реорганізація кодової бази без зміни зовнішньої функціональності (`/src`).
- **docs:** Зміни в документації проєкту, архітектурних схемах та інструкціях (`/docs`).
- **gate:** Фіксація рішень контрольних точок, аудитів та журналів вирішення конфліктів (`/logs`).

## Формат повідомлення
`<префікс>: <лаконічний опис змін у наказовому способі або доконаній формі>`

### Приклади:
- `spec: update volume load calculation constraints`
- `fix: correct division by zero in 1RM calculation`
- `gate: resolve human-agent conflict on 1RM model`
